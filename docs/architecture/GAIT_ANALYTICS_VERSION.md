title: Gait Analytics Versioning
---

## Overview

The gait analytics thresholds are centralized in `src/lib/gaitConfig.ts`.

To guarantee cross‑platform and cross‑service parity we derive a deterministic short hash (FNV‑1a 32‑bit) over the stable JSON shape of the config:

```ts
export const GAIT_ANALYTICS_VERSION = <8 hex chars>
```

Artifacts generated by `pnpm gait:sync` now embed this version:

| Artifact | Field | Purpose |
|----------|-------|---------|
| `src/fixtures/gait-config-export.json` | `version` | JS/Worker parity & drift guard |
| `ios/HealthKitBridge/Generated/GaitConfig.swift` | `version` | iOS parity test |
| Worker endpoint `/api/gait-config-version` | `version`, `config` | External verification |

## Update Workflow

1. Edit `src/lib/gaitConfig.ts`
2. Run `pnpm gait:sync`
3. Run `pnpm test -- gaitConfigSwiftParity gaitAdvancedGuards`
4. Commit updated TS + JSON + Swift artifacts
5. CI `gait_config_integrity` job will fail if you forget step 2.

## Rationale

* Enables mobile / backend / analytics pipelines to assert they use the same thresholds.
* Hash is short, stable, and reproducible without needing a semantic version bump.
* Facilitates future A/B or staged rollout (serve both versions; clients self‑identify expected hash).

## Future Extensions

* Maintain a `history/` directory with prior configs and hashes for audit.
* Add optional query param `?expected=<hash>` to endpoint to return 409 on mismatch (for proactive monitoring).
